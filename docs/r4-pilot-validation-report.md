# R4 pilot protocol validation report

Status: protocol documentation validated offline; comparative collection and results pending.

## Validated in this change

The strict protocol and synthetic JSON example define two exactly matched conditions, frozen task-contract and acceptance identities, deterministic distinct-participant assignment, call/time bounds, a follow-up window, and local evaluation consent. The offline observation contract separately preserves terminal outcomes, every attempt, requested and reported provider settings, active human-effort categories, check identities and statuses, timestamp-bound escaped-defect follow-up, aggregate finding and repair observations, and nullable usage and cost. Acceptance claims require a passing task-bound protected check; first-pass success additionally requires observed zero human source-edit minutes. The operating protocol adds separate repository authorization, artifact-sharing choice, external secret-exclusion prerequisites, and descriptive-only interpretation. Finding/repair aggregates remain operator observations rather than independently traceable adjudication records.

The focused offline suite passed 26 tests across the pilot ledger, actual CLI and documentation. The tests parse and initialize the strict example, exercise frozen deterministic assignment, immutable observations and feedback, task-bound acceptance evidence, zero-edit first-pass semantics, elapsed follow-up windows, complete denominators, explicit failures and reason categories, nullable effort and usage, assignment-keyed reported-setting and resource deviations, matched-pair accounting, neutral reports, tamper rejection, concurrent-record exclusion, and the command surface: `pilot init`, `pilot status`, `pilot record`, `pilot feedback`, and `pilot report`. This validates the local synthetic fixture path; it does not mean that comparative collection or a live pilot ran.

The repository-wide Python suite ran 292 tests: 289 passed and 3 unchanged host-bound checks skipped. The skips were two nested Seatbelt checks that cannot initialize inside the managed execution context and one unavailable loopback preview check; none was retried without its required guard. Eight dependency-free Node terminal tests, installed-wheel resource checks, `agentkit check`, compilation and diff hygiene also passed. No live inference, repository collection or network installation was used.
