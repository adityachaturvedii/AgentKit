# R5 product-path validation report

Status: offline implementation foundation complete; real provider and browser acceptance pending.

## Implemented and fixture-tested

The existing provider-planned static-web workflow now validates bounded acceptance and exact required quality stages, records finalized node routes, and counts every planning attempt before admitting the remaining mandatory work. Assignments still run through the existing branches, isolated worker copies, controller integration, protected mechanics verification, independent review, bounded repair and authentication contracts. No game-specific graph or finished product is embedded in the harness.

The preview owner copies only the reviewed tracked manifest into a fresh private plain-file tree. Snapshot identity includes file bytes, executable semantics and candidate revision; `.git`, untracked files, symlinks and path escapes are excluded. The foreground owner serves the snapshot, removes it on shutdown and stores a content-addressed stopped-session receipt.

Browser evidence is strict, bounded and bound to the exact candidate, preview session and snapshot. It records browser name/version, an external human or driver identity distinct from implementation providers, each predeclared action/assertion/observation, optional contained hash-checked screenshots and an explicit visual pass/fail. This validator does not run a browser. Product packages declare current mechanics, independent-review, browser and approval evidence and pass the same non-executing portable export/verifier used by repository work.

## Validation boundaries

All new behavior is validated with deterministic providers, disposable Git repositories, plain snapshots, synthetic stopped-session receipts and fixture browser reports. The focused product/browser/package/distribution/documentation suites ran 44 tests: 43 passed and the managed-context loopback check skipped. The repository-wide suite ran 287 tests: 284 passed and 3 unchanged host-bound checks skipped. Eight dependency-free Node terminal tests, installed-wheel checks, structural validation, compilation and diff hygiene also passed. No provider inference, login, network dependency installation, personal repository, publication or browser automation was used.

The managed test context may prevent loopback bind and nested Seatbelt initialization. Those checks remain skipped rather than retried without their required boundary. A future supported-host trial must separately establish the effective macOS verifier boundary, loopback serving, actual browser interaction, accessibility and visual behavior, provider routing and live usage.

## Remaining limitations

- Browser reports remain externally supplied evidence; integrity validation does not prove the interaction occurred.
- Browser credentials, egress and process containment are not established.
- Planning-stage authentication recovery is not implemented; authentication failure blocks the fresh submission.
- The profile supports trusted controller-created dependency-free static products only. Package installation, backends, service workers, hostile inputs and general repositories are unsupported.
- Crash-safe preview recovery and detached browser/process cleanup are unsupported.
- No live product, Breakout completion, approval, push, PR, merge or deployment is claimed.
