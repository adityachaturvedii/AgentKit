# Acceptance design

Read the shared [authority and evidence rules](../../docs/skill-contract.md). Use frozen requirements, public interfaces, approved runtime facts, and existing discovery evidence. Do not inspect the candidate implementation, expected patch, controller database, approval state, or worker write paths.

Map each material requirement to an existing-repository, proposed, protected-independent, browser, or manual check. Record the expected result and its source, bounded runtime/argv proposal, nonempty discovery rule, known-good control, intentional-defect control, and distinct product, harness, runtime, and unresolved failure categories. Compare cross-realm JavaScript values and errors by required observable semantics rather than constructor identity.

Return a version 1 `acceptance-design` handoff for controller validation. It cannot install, freeze, execute, weaken, or pass its own oracle. If no controlled runtime exists, report the capability gap.
