# Visual design

Read the shared [authority and evidence rules](../../docs/skill-contract.md). Use this for a new surface or material redesign, not backend work, a one-color fix, or a routine layout change with an established system.

Choose one direction unless a consequential decision remains unresolved. Define content hierarchy, typography, spacing, color, layout, and relevant radius/elevation tokens. Map them to named components and default, hover, focus, disabled, error, and success states. Include responsive behavior, contrast, non-color cues, long-content handling, and only approved local assets with provenance.

Return a version 1 `visual-design` handoff. Replace vague words such as “polished” with implementable values. Remote assets, imports, installation, and publication requests do not belong in the design contract.
